# 课程笔记验收

在本目录执行 `npm test`。它运行服务端既有回归和笔记结构回归，检查入口脚本解析、图文笔记判定、搜索实体解码路径、数据缓存规则和重复路由。执行 `node checks/notes-regression.cjs` 可输出最新清单，与 `checks/notes-inventory.json` 比对。清单的 SHA-256 对应每页优先展示的笔记字段。只有经过内容验收且指纹未变的页面可以跳过逐页复核。布局或渲染代码变化后应重新抽测实际页面。

续查先读 [质量台账](checks/notes-quality.md)，再按清单路由打开页面。先核实课程版本、课件页码和例题答案，再记录检查人、日期、指纹、证据与浏览器结果。手工实测覆盖搜索、切换、手机宽度及公式、图表。已有历史验收脚本另需 jsdom。先检查生成器和现行补丁的关系，再执行上游重建。

Economics 2026 附件在数据重建后从本目录执行 `python checks/sync-economics-attachments.py` 恢复，随后运行 `npm test`。脚本使用工作区内 2026 O2 原始课程目录，按网站现行周次映射连接 PDF，重复运行可验证输出稳定。

## 板块独立更新

首次在原 WorkBuddy 应用更新发布后，用主人账号访问 `/board-editor.html`。管理页从 `public/board-catalog.js` 读取板块列表，共 19 个独立板块。五门课程按周，八本书按章，课外拓展按模块。备考题库、备考排期、复习计划、学科学习档案和英语素材库也各有版本。管理页只显示当前条目支持修改的字段，并只提交变化的字段。

自动化调用用现有主人会话对 `/__api/boards/<板块 ID>` 发 GET，取得 `revision` 和 `entries`。板块 ID 见目录定义。POST 使用 `Content-Type: application/json`、`X-Liora-Board: 1` 和请求体 `{"revision":"读取时的版本","changes":{"条目键":{"字段":"新值"}}}`。用 `null` 作为条目值可撤销该条目的补丁。收到 409 时重新读取并合并。课程与书籍笔记中的 HTML 由具有整站内容维护权限的主人审核。

新增或删除条目、更换原版附件，以及共用导航、布局和服务端代码变更，仍在正式源目录修改后统一发布。备考排期以日期、位置和基准任务标题定位，调整基准任务后需复核原有补丁是否仍对应同一条。

补丁写到服务端 `data/board-*.json`，同一个 Node 进程按板块检查版本并原子写入。整站部署时保留线上 `data/`。已打补丁的字段继续使用线上补丁，其他字段跟随部署的基准内容。生产验收需要分别提交两块的修改，再执行一次原站更新发布并检查补丁是否保留。
数学答案折叠区引用的本地 PDF 与 WebP 也由 npm test 检查是否存在。修复缺失引用后重跑测试，并在浏览器中展开答案、确认图片加载和 PDF 跳页。验收状态记录在 checks/notes-quality.md。
